# 01: Railhead v2 — spine-first plans, behavioral probes, corrective group gates, test hardener

**What to build:** Redesign railhead's ticket model and gating so an unattended build with cheap models costs ~1h for a spriteforge-size app and never produces a worse artifact than a pure unsteered opencode run, even when all judging gates are broken or skipped. Diagnosis is grounded in the run at ~/projects/spriteforge/.railhead/run-20260925-1237 (state.json: 12 tickets committed in 89 min of build, 40 min of advisory goal probes, 543 builder round-trips, 240k output tokens, goal_reviews recording the same blockers 4 times unfixed, one errored review logged as "passed (minor only)", visual_rounds = -1, app shipped as an unwired 32x32 fragment in a 512x512 canvas). Read first: AGENTS.md, CONTEXT.md, docs/adr/0007, 0022, 0025, 0029, 0032, 0039, 0040, 0043-0049, then the seams named per step. Everything green every step (ADR 0006): each sub-change lands with npm test green. The 8 pieces, in execution order:
1. TICKET GRAMMAR — behavioral criteria with probe lines, no self-tests. In src/core/ticket.ts (render/parse) and the planner ticket prompt in src/plan/plan.ts (coupled per ADR 0007 — change together): a criterion is an observable behavior sentence, optionally followed by an indented probe recipe line ("probe: launch; <action>; <assertion>") that a cheap judging seat can materialize into a deterministic script. The planner prompt must stop emitting "(test)" criteria and instead describe what an observer can verify on the running artifact. Parser keeps render/parse round-trip; legacy "(test)" criteria still parse as plain behaviors; assertTicketsUsable no longer ties criteria to tests.
2. SPINE-FIRST PLANNING + PLAN GATE. src/plan/plan.ts design call gains an ordering rule: the first one or two groups must deliver a launchable, visibly correct vertical slice (for browser-ui: shell renders the core surface and one primary action visibly works); deep-logic tickets must not all precede UI composition. src/plan/planner.ts adds one plan-gate call after finalizePlan: the goal-review seat diffs PLAN.md/docs against the original prompt's goal checklist and returns scope-gap findings or $REPLAN — reuse replanFromCheckpoint machinery and the max_replans budget. Gap findings that today surface 30 min into a run (missing owner for named deliverables) must fail the plan before any build starts.
3. PERSISTENT PROBE REGISTRY. New .railhead/probes/ plus state.probes (load/save via the ledger, resume-safe). The goal-review seat materializes probe scripts once per group (it already writes ad-hoc probe files); later rounds first run registered probes deterministically and judge their output, re-deriving only what behavior changed. This blocks the observed waste: 4 goal rounds of 10-15 min re-probing the same blockers. Probe scripts must stay language-agnostic: a probe is a command + expected predicate, never a hardcoded test framework in prompts.
4. INTERACTION SMOKE AS BLOCKING GROUP GATE. In src/gates/interaction-smoke.ts and run.ts: interaction_smoke defaults on when projectInterface is browser-ui (DEFAULT_CONFIG/preset change, no longer planner-seeded); it runs once per committed group boundary, blocking. Its prompt is strengthened past DOM-only: require a render-delta check (sampled visual output changes after a real action) and zero console errors. The failure it catches first is "app launches, request 200, canvas is an unwired rect" — today curl-smoke passes that and the artifact ships. Keep inconclusive != failure and the existing step budget: a seat that cannot prove anything must not hard-block the run.
5. GOAL CHECKPOINT AUTHORITY. Flip the light-preset default in src/config/config.ts (goalCheckpointActionFor) so mid-run goal checkpoints are corrective-anchored, not advisory: anchored [BLOCKER] findings splice corrective tickets ahead of the frontier via the existing processCorrectiveFindings; unanchored/steering-only findings stay advisory; replan stays max_replans-capped. In goal-loop.ts, before a re-review, first re-verify ONLY previously open blockers using the probe registry, then expand. Findings closed between rounds must not be re-found — that is what currently burns 10-minute probe rounds repeating identical findings.
6. NO PER-TICKET CODE REVIEW UNDER CHEAP PRESETS; A DEAD GATE IS NEVER GREEN. Light/medium presets stop scheduling per-ticket code review (judged diffs from a same-tier judge caught nothing this run; group probes and run-end structural review carry the signal). In src/gates/reviewer.ts and its run.ts caller: a reviewer invocation that exits non-ok is classified infra via the failure ladder, never a minor-item pass — the log line "review passed (minor only)" must be impossible without a review transcript. Same invariant wherever a gate records a verdict without having run (visual_rounds = -1 while claiming coverage is the same class of lie).
7. BUILDER SURFACE CADENCE + MARKER LENIENCY. In src/context/builder.ts: the open-ended screenshot cadence (capture, read back, judge, iterate) generalizes from the single craft ticket to every ticket whose criteria touch the visual surface (use the existing surface classifier), gated by the measured vision capability. The design doc is re-injected deterministically on every surface-ticket invocation — do not trust post-compaction re-read discipline from a cheap model. In src/core/checkpoint.ts: normalize zero-padding (ticket=1 matches ticket 01) and accept a trailing-marker variant instead of re-invoking; an ended turn with verify green for the current ticket counts as the checkpoint (marker stays primary; this is a fallback, never a precheck of unverified work). The five wasted invocations observed (01, 07, 10, 12 twice) become impossible by construction.
8. TEST HARDENER AT RUN END. A final ticket ("harden") is appended after the planned frontier: it transcribes behaviors confirmed by the probe registry into a committed regression suite using the project's own test stack, added late when that stack exists. Builder prompts stop carrying "(test)" asks during the build; verify still passes at every step because verify runs only what exists — the suite grows at the end from confirmed behavior, not from the implementer imagining its own grade.
Docs: update or amend the ADRs — 0007 (new ticket grammar), 0029 (advisory default flipped to corrective-anchored), 0039/0049 (plan gate is the coverage check's new home), 0043/0044 (probe registry + blocker fast-recheck), 0006 (verify excludes builder-authored tests until the hardener) — plus one new ADR: a gate verdict is not green unless the gate actually ran. Update root and module AGENTS.md files wherever these behaviors are described.
